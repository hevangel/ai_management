# 當代碼變得充裕：重新思考 AI 時代的工程績效

## 商業難題

在軟件工程的大部分歷史裡，執行容量是稀缺的。把一個想法變成能運作的軟件需要大量人力，而圍繞工程師建立的績效體系——代碼行數、commit 數目、pull request、完成的工作單、交付速度——全都建立在同一個隱含假設之上：可見的活動就是人類努力的證據，因為產出這些活動成本高昂。

AI 編程工具正在打破這個假設。AI 編程助理的對照研究已顯示任務完成速度有大幅改善，工程師如今能以相對極小的增量精力，產生代碼、測試、文件、設計方案和實作計劃。管理者慣常點算的活動正變得廉價——當一項中間產出變得便宜，點算它便再也無法說明背後稀缺能力的多寡。

這帶來一個令人不安的量度難題。組織對工程活動的可見度達到史上新高，卻正是在活動最能虛假反映價值的時刻。一個繼續獎勵可見產出的績效體系，會很理性地獎勵「生產力表演」：更多服務、更多複雜度、更多審查負擔、更多下游成本——而那些防止不必要工作、消除不確定性、行使判斷力的工程師，在紙面上反而像組織裡生產力最低的人。

對工程領袖而言，問題已不再是「這位工程師產出了多少？」而是：**因為這位工程師的存在，哪些事情變得更清晰、更安全、更簡單、更有價值——而哪一種管理體系能夠識別出這一點？**

## 我們的發現

從五個分析視角——管理理論、管理實務、企業營運模式、競爭策略，以及經濟決策——得出一幅一致的圖景：

1. **稀缺資源已向上游轉移：由執行轉到判斷。** 傳統生產鏈由人力努力到工程活動，再到軟件產出，最後到商業成果，活動是努力的可見代理指標。AI 把機器執行插入這條鏈：一單位的人類判斷如今能產生遠為更多的可見活動。當活動與貢獻之間的相關性持續惡化，績效管理必須追隨稀缺資源——轉向問題界定、降低不確定性與決策質素。

2. **量度「獲分派的難度」，會反向獎勵保留複雜度的行為。** 優秀工程師總能把困難問題做得看起來容易：花兩天釐清需求、消除依賴、簡化架構，本來「極端」的項目便變得直接。更有用的量度是**已退役的難度**（difficulty retired）——工程師消除了多少不確定性、複雜度、依賴與營運風險。許多最有價值的工程工作，產出的不是代碼，而是知識。

3. **五個維度，識別出活動指標看不見的績效：** 問題界定（解決正確的問題）、降低不確定性（把未知變成已知）、判斷力（在 AI 生成的方案之間作出取捨）、負責任的交付（可靠性、安全與可維護性，而非把成本轉嫁審查者與營運團隊），以及槓桿效應（令身邊的組織更有能力）。

4. **量度 AI 使用量，只是用更好的儀器重複舊錯誤。** Prompt 數目、token 消耗、採納率、AI 生成代碼百分比，都是使用率指標，不是績效。真正的問題是 **AI 槓桿效應**：工程師能否把 AI 能力轉化為更好的成果，而不把不成比例的驗證成本轉嫁給同事。

5. **遙測數據是證據，不是判決。** 高 revert 率、巨型 pull request、一連串事故，無辜的解釋往往與有罪的解釋一樣多。工程數據應該觸發提問，而不是自動產生評級——組織更應劃下一條清晰的架構界線：AI 可以收集和整理證據，評估的問責仍然由人類承擔。監控員工的 prompt 得不到多少洞見，卻會賠上信任。

6. **當代碼變得充裕，克制便成為頂級貢獻。** 工程師若看得出五個 AI 生成的服務全都沒有必要，重用現有元件並刪掉數千行代碼，創造的價值高於把它們全部上線的同事。每個產物都帶來未來的義務——測試、安全、營運、維護——實作正變得充裕，複雜度卻沒有變得免費。繼續點算工程工作「廢氣」的組織，將越來越認不出自己最好的人才。
