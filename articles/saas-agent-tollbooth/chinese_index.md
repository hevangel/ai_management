# 賣的是工作，不是門口：SaaS 如何在代理時代勝出

*為何強迫客戶使用專有代理、藉此加價轉售模型用量，是一個薄弱的長期策略——以及為何「受控開放」加上以受治理的執行作為產品，才是更強的路線。*

一位 SaaS 高層的構想，大概是這樣：*我們在產品中內建 AI 代理，以批發價購入基礎模型的推理服務，向客戶收取可觀的倍數，並確保客戶不能把任何競爭對手的代理指向他們自己的數據。* 收入的好處顯而易見：客戶已被軟件綁定、AI 是最熱門的預算項目，而 token 的加價看來像是免費的錢。

本文認為，對大多數處於競爭中的 SaaS 公司而言，這個策略方向有誤。它在未來數年或許確實能增加收入。但如果 AI 能力持續進步、推理成本持續下降，「智能」的加價將愈來愈透明、愈來愈容易受到挑戰；一家把策略建基於把守門口的公司，會發現門後的智能已變得廉價而可互換。

更持久的模式是**受控開放（controlled openness）**：向獲授權的外部代理開放產品的數據與行動層，同時銷售一個在便利性、可靠度、治理、整合與成果保證上勝出的第一方託管代理。這個但書很重要：SaaS 公司不需要免費送出 API 存取權、不需要讓任意代理無限制地執行動作、也不需要以成本價出售自己的代理。它可以收取可觀的毛利。但這些毛利應該附着於受治理的執行、領域工作流程的專業、驗證、風險轉移、合規、人手例外處理與可量度的商業成果——而不是靠令其他智能供應商無法接入。

## 兩個並非對立的想法

上述構想其實捆綁了兩個獨立的想法。

第一，是**按完成的工作計費，而非按原始 token 計費**。第二，是**禁止客戶使用任何競爭對手的代理或模型**。第一個想法可以非常出色；第二個通常才是危險之處。

客戶一般不想購買四萬個輸入 token、六次檢索操作、三次工具呼叫和兩次重試。他們想要的是：一宗支援個案得到解決、一張發票完成對賬、一份合約完成審閱、一項配置完成更改、一位客戶完成入門、一個工程故障得到診斷。SaaS 供應商完全可以把不確定而複雜的 AI 成本，轉化為簡單的商業價格——就像雲端服務商收取的是託管資料庫的費用，而不是逐條列出每個 CPU 指令和磁碟操作。

問題出現在策略變成：*我們的代理不需要是最好或最便宜的，因為我們會阻止其他所有代理存取客戶自己的數據和工作流程。* 那不是 AI 護城河，而是通行費。

## 為何原始智能是建立護城河的差地方

推理的經濟學正朝着不利於簡單 token 套利的方向發展。史丹福大學 2025 年《AI 指數報告》發現，以約相當於 GPT-3.5 基準品質查詢模型的成本，由 2022 年 11 月的每百萬 token 20 美元，降至 2024 年 10 月的 0.07 美元——跌幅逾 280 倍。視乎任務，觀察到的推理價格跌幅由每年約 9 倍至 900 倍不等，硬件的性價比也在快速改善。

這並不表示每個前沿模型都會持續變便宜。最新的推理模型可能依然昂貴，而代理透過規劃、重試和工具使用，可以消耗大量推理。但這確實意味着，SaaS 公司不能穩妥地假定，今日的模型成本是持久的定價能力來源。

同時，代理的能力也在快速提升。METR 對軟件任務的量度發現，前沿代理能以 50% 可靠度完成的任務長度，歷史上大約每七個月翻一番，儘管 METR 強調方法學上存在相當不確定性，並沒有聲稱這趨勢必然持續。史丹福 2026 年《AI 指數報告》指出，電腦操作代理在 OSWorld 上達到 66.3%，但在結構化的代理基準測試中，仍有約三分之一的嘗試失敗。

這些發現同時指向兩個方向：模型已強大得足以威脅單薄的 SaaS 包裝層；但它們又依然不夠可靠，令編排、控制與問責仍有價值。這個組合，正是託管代理可以成為有價值產品、而單靠轉售 token 卻是薄弱護城河的原因。

## 模型進步時，價值移往何處

分析市場的一個有用方法，是把 AI 技術棧分成多個層次。隨着智能變得更可互換，價值會轉移到模型無法自行製造的資產：採取行動的權限；取得權威數據的途徑；對「成功成果」長甚麼樣子的認識；業務規則；審批鏈；歷史上的例外；結果出錯時的法律責任；以及與組織其餘部分的整合。

因此，勝出的 SaaS 公司，不大可能只是擁有聊天機器人的那一家，更可能是擁有聊天機器人背後*可信執行環境*的那一家。

## 為何按成果計費可以是非常好的模式

相對模型成本的高加價，本身並無不妥。試想一項假設的任務：15,000 個輸入 token、3,000 個輸出 token，假設模型價格為每百萬輸入 token 3 美元、每百萬輸出 token 15 美元。第一輪的模型成本約為 0.09 美元：輸入 0.045 美元，輸出 0.045 美元。

再加上交付成果的其餘真實成本：預期重試約 0.04 美元、檢索與工具服務 0.03 美元、監控與記錄 0.02 美元、以期望值計的人手例外處理 0.25 美元，以及支援、安全與責任準備金 0.10 美元。整體預期成本約 0.53 美元。

如果以 2 美元出售這項成果，毛利率接近 74%。倘若該任務過去令客戶花費 10 或 20 美元，而供應商保證結果，這完全可以是合理的。客戶購買的並不是 9 美分的 token，而是一個運作中的工作流程、可預測的成本、更少人手做重複工作、與業務記錄的整合、例外處理、服務水平承諾，以及出事時可以致電的對象。

HubSpot 提供了一個有用的真實例子。2026 年 4 月，它把客戶代理（Customer Agent）改為每個已解決對話 0.50 美元、把潛在客戶開發代理（Prospecting Agent）改為每條推薦線索 1 美元，而不是只按啟用或對話量收費。HubSpot 表示，它之所以能這樣做，來自與其 Smart CRM 情境的整合。它報告客戶代理能解決 65% 的對話，並將解決時間縮短 39%，但這些數字是供應商自行報告，而非經獨立稽核。

這更接近一個站得住腳的商業模式。它說的是：*我們對客戶、歷史和工作流程的了解，足以讓我們承擔績效風險。* 這與以下說法截然不同：*我們把你的提示詞轉交給模型，然後向你收取 API 成本的二十倍。*

## 「完成任務」的定義就是一切

當供應商同時控制執行工作的代理，以及判斷工作是否成功的定義時，按成果計費就變得危險。

以「已解決的支援對話」為例。是指代理發出了最終答覆？客戶沒有即時回應？工單保持關閉七日？無需人手介入？客戶確認了方案？帳戶其後沒有被退款？每種定義都會產生不同的價格與不同的誘因。

一份穩健的成果合約，應列明可觀察的完成事件、品質門檻、可撤銷或重開的時間窗口、人手升級規則、退款或抵免規則、部分完成與重複任務的處理，以及稽核證據。對於財務對賬，「完成」可能指交易已匹配、通過所有控制、已過帳至總帳，且三十日內沒有被沖銷。對於支援任務，則可能指客戶已確認解決、沒有人手接管，且個案在七日內沒有重開。

沒有這樣的定義，「按完成任務付費」可能淪為一個貼上樂觀標籤的變相用量計費。

## 為何禁止外部代理在策略上有風險

### 企業正走向多模型

大型客戶愈來愈不希望每個 SaaS 供應商都代他們選擇獨立的模型、安全政策與 AI 計費系統。他們可能已有企業級 OpenAI 協議、Microsoft Copilot、經 AWS 或 Google Cloud 使用的 Anthropic、內部模型閘道、本地部署的開放權重模型、集中的記錄與數據外洩防護控制，以及針對不同數據分級而獲批的模型。

麥肯錫 2025 年的調查發現，88% 的受訪者表示至少在一個業務職能中使用 AI，但近三分之二尚未開始在企業範圍內擴展。62% 至少在試驗代理，而只有 39% 報告企業層面的 EBIT 影響。換言之，瓶頸不單是取得模型，而是擴展、工作流程重新設計與營運控制。德勤的調查同樣指出，法規遵循、風險管理與欠缺治理模式，是部署的主要障礙。

因此，一個 SaaS 供應商若說「你必須使用我們的模型採購、我們的代理運行環境和我們的治理層」，就可能與客戶的企業架構相衝突。

### 模型抽象化正成為常規基礎設施

多個主要的企業平台，現在都刻意把模型供應商抽象化。Snowflake 的 Cortex REST API 支援 OpenAI 相容與 Anthropic 相容介面，並在共同的治理邊界內提供來自 OpenAI、Anthropic、Meta、Mistral、DeepSeek 與 Snowflake 的模型。Amazon Bedrock 支援逾一百個模型，並提供與模型無關的 Converse API，以及 OpenAI 相容與 Anthropic 相容介面。Oracle 的 OCI Responses API 與 OpenAI 相容、支援多個模型家族、提供模型路由，並透過 MCP 連接外部工具。Databricks 在共同的託管介面背後，支援來自 OpenAI、Anthropic、Amazon Bedrock、Google Vertex AI 以及 OpenAI 相容自訂供應商的外部模型。

策略訊號十分清晰：企業客戶愈來愈期望模型是可替換的組件，而非永久與每個應用程式融為一體。把產品經濟模式緊密綁定單一模型供應商的 SaaS 公司，有可能成為客戶技術棧中最僵化的一環。

### 外部代理正成為新的互動系統

過去，SaaS 應用程式同時擁有記錄系統與用戶介面。AI 可能把兩者分開。客戶偏好的代理，可能成為「互動系統」（system of engagement），而個別 SaaS 產品則成為記錄、政策、行動、運算與驗證的系統。

試想用戶向一個企業代理說：*找出延誤的貨件、查看客戶的支援歷史、判斷是否可給予補償、發出補償、更新 CRM，並通知客戶經理。* 這個流程可能橫跨五個 SaaS 系統。用戶不想與五個不同的專有代理進行五場對話。一個拒絕參與跨應用程式工作流程的 SaaS 應用，就成了障礙——而如果有開放的競爭對手能提供相同的核心功能，客戶可能寧願更換 SaaS 產品，而不是更換企業代理。

### 關閉 API 並不能消除自動化

商用代理平台已支援瀏覽器與桌面自動化。例如 Microsoft 的 Copilot Studio，就支援以 OpenAI 與 Anthropic 模型進行電腦操作的工作流程。因此，封鎖 API 存取未必能阻止外部自動化，反而可能把自動化推向螢幕擷取、模擬點擊、瀏覽器控制、檔案匯入匯出，以及電郵式互動——這些做法通常比一個設計良好的 API 更脆弱，也更難治理。

從安全角度看，較好的立場往往是：給獲授權的代理一個狹窄、可稽核、受權限限制的介面，而不是迫使它們透過圖形介面偽裝成人類。

## 開放協議是競爭格局的一部分

模型情境協議（Model Context Protocol，MCP）是連接 AI 應用程式與工具、數據來源及工作流程的開放標準；其文件描述了一個廣泛的客戶端與伺服器生態系統，包括 ChatGPT、Claude、開發工具與其他代理平台。Agent2Agent（A2A）協議處理的是代理之間的溝通，而非只是代理與工具之間的存取。Google 於 2025 年把 A2A 移交給 Linux 基金會，創始參與者包括 AWS、Microsoft、Salesforce、SAP、ServiceNow 與 Cisco，並報告當時有逾一百家公司支持。

這些標準可能改變或被取代。它們的重要性不在於 MCP 或 A2A 必然永遠勝出，而在於市場的方向：客戶與大型科技供應商正試圖令代理與工具可互通，而採用刻意不相容架構的中小型 SaaS 供應商，是在押注反對這個方向。

## 領先供應商實際上在做甚麼

市場並非趨向「一切免費開放」，而是趨向**開放連接，加上專有而計量的價值**。

**ServiceNow 開放行動系統，並對執行計量。** 它可能是目前最接近本文所主張模式的例子。2026 年 5 月，ServiceNow 宣布其「行動系統」（system of action）將透過其 MCP 伺服器，向任何獲授權的代理開放——包括 Claude、Copilot 及客戶自建的代理。執行並非免費：無頭（headless）行動所消耗的，是與 ServiceNow 自家 AI 產品相同的商業貨幣。ServiceNow 亦套用身分檢查、權限、OAuth、稽核軌跡、工作階段控制，以及按角色劃分的工具包。其 AI Control Tower 旨在跨其他系統，治理原生與第三方的代理及模型，提供可觀察性、風險控制與開支量度。這些是該公司自己的產品聲稱，但其策略架構值得注意：它力求成為受治理的執行層，無論由哪個代理擁有用戶介面。外部代理成為分銷渠道。每當外部代理需要執行企業動作，ServiceNow 都可以驗證其身分、套用工作流程、執行政策、記錄交易，並對該次執行收費。這遠比要求每位用戶從 ServiceNow 的聊天視窗開始，更站得住腳。

**Salesforce 對行動收費，同時支援外部工具。** Agentforce 提供多種定價方式：每十萬 Flex Credits 500 美元、每次對話 2 美元、按用戶授權，以及固定費用存取。其定價示例計量的是行動，而非直接顯示原始的模型 token 成本；一個使用兩個行動的「我的訂單在哪裏？」工作流程，示例為 40 點數，即 0.20 美元。Salesforce 亦已加入原生 MCP 客戶端支援，並可存取夥伴的 MCP 伺服器。它試圖保住自己的代理平台與商業計量，同時不令自己與更廣闊的工具生態系統隔絕。

**Microsoft 以共通點數計量各類異質工作。** Copilot Studio 對傳統回答、生成式回答、代理行動、圖譜依據（graph grounding）、流程執行與進階推理，收取不同數量的點數，而其電腦操作功能，可在同一代理產品背後採用不同的模型供應商。這種模式並非免費推理，而是一個計量的代理平台，並對底層智能保持彈性。

**HubSpot 對已驗證的商業事件收費。** 它轉向按已解決對話和推薦線索定價，是直接嘗試令計費與客戶價值而非模型消耗對齊——對那些不想設計模型路由或治理基礎設施的中小企客戶尤其有吸引力。

**Atlassian 對較高運算量的代理功能使用點數。** Rovo 代理請求消耗點數，普通請求、Deep Research 與其他高運算量功能的消耗量各不相同。這顯示了一個中間階段：客戶並非直接購買 token，但價格仍然更貼近運算工夫，而非有保證的商業成果。

**基礎設施供應商以模型選擇競爭。** Snowflake、AWS、Databricks、Oracle 與 Google Cloud，愈來愈把模型選擇與共通介面當作賣點，而非問題。這些公司影響着企業架構，因此試圖硬性鎖定模型的 SaaS 供應商，可能是在對抗客戶在別處正採用的採購與治理模式。

## 封閉路線最有力的論據

封閉路線並非不理性，偏好第一方代理有其正當理由。

*端到端的品質控制。* 供應商可以測試已知的模型、已知的提示詞、工具、數據格式與重試政策。支援任意外部代理，會令失敗組合成倍增加。

*安全與合規。* 治理不善的外部代理可能擷取過多數據、洩露機密、執行未經授權的寫入、誤解審批要求，或製造難以管理的支援事故。

*可支援性。* 當供應商控制整個技術棧，支援團隊可以重現問題。面對未知的客戶模型與編排框架，責任便變得含糊。

*更簡單的產品體驗。* 大多數客戶，尤其是較小的客戶，不想選擇模型、配置憑證、監察 token 用量或維護代理基礎設施。

*更好的優化。* 供應商可以對簡單步驟用較小的模型、對困難決策用較大的模型、盡可能用確定性代碼，並在需要時升級到人手處理。其整體成本可能低於客戶自行實作。

*數據與回饋的飛輪。* 第一方代理能收集更好的失敗、更正、被接受的建議、被拒絕的動作與特殊個案的資訊，並隨時間改善工作流程。

這些都是令供應商的代理成為預設且得到最佳支援之選項的好理由，但它們本身並不足以成為令其成為技術上*唯一獲准*選項的好理由。

## 封閉策略何時可以勝出

在某些情況下，封閉策略可能長期保持盈利。

如果供應商擁有**近乎壟斷的市場力量**——產品極難被取代，並控制獨特的記錄系統——客戶可能接受被迫使用代理。但這靠的是分銷與轉換成本，而非更優越的 token 轉售模式。

如果任務**受高度監管或具危險性**——放行付款、修改醫療記錄、批核保險索償、改動安全關鍵基礎設施——供應商可能需要認證整個工作流程，包括模型與代理運行環境。外部模型最終仍可能被允許，但須透過相容性與批准計劃。

如果供應商**承擔重大責任**，一家保證成果正確性的公司，合理地要求控制執行技術棧。

如果**客戶壓倒性地偏好簡單**，例如在很多中小企軟件中，即使技術上可以自帶模型，一個只有一張賬單、毋須配置的整合代理，也可能佔主導地位。

而如果限制只是**暫時的**，那是另一回事。在產品早期，供應商可能只支援第一方代理，同時開發權限模型、稽核、速率限制、外部代理認證與穩定的行動 API。基於產品成熟度的暫時限制，並不是永久的收費站。

## 為何受控開放勝過兩個極端

學術界有關平台的文獻，有助釐清這個選擇。Kevin Boudreau 對掌上電腦平台的研究，區分了「授予存取權」與「放棄控制權」。在所觀察的樣本中，向獨立互補者提供更大的存取權，與新裝置開發加速多達五倍相關，而放棄對平台的控制，帶來的額外效果則小得多。

這個教訓並不是每家 SaaS 公司都應該開源，而是：公司可以向互補者開放存取，而不必放棄核心平台的擁有權、治理或變現。供應商可以保留對身分、授權、業務規則、交易完整性、認證、API 版本、速率限制、稽核與商業條款的控制，同時讓客戶與夥伴在代理層面創新。

這就是受控開放。

## 平台包抄的風險

平台包抄（platform envelopment）的文獻描述，相鄰平台市場中的公司，如何把自己與用戶既有的關係捆綁進另一個市場，從而削弱現有企業對客戶介面的控制。應用到 AI，潛在的包抄者包括 Microsoft Copilot、ChatGPT、Claude、Google 的代理生態系統、企業代理平台，以及客戶自建的內部助理。它們可能成為用戶開始工作的地方，而個別 SaaS 產品則成為該介面背後的工具。

封閉的 SaaS 公司可能嘗試以拒絕存取來阻止包抄。當它擁有強大的市場力量時，這或許有效。但對於可被取代的 SaaS 公司而言，客戶可能只是回應：*我們已統一使用企業代理；我們會購買能與它配合的應用程式。*

因此，防守策略未必是擁有聊天視窗，而是令底層系統不可或缺。即使對話由另一家公司擁有，行動系統供應商仍可捕捉價值。

## 衝突背後的按席位定價問題

許多 SaaS 公司害怕外部代理，原因與安全無太大關係：代理威脅按席位（per-seat）定價。

假設一家公司有一千名員工使用某 SaaS 產品。一個中央代理可能讓其中二百人——甚至二十個自動化身分——完成大部分相同的工作量。如果收入完全依賴人類席位，開放代理存取可能令收入下降，即使產品使用量上升。這就產生了禁止外部代理、迫使每位用戶經由持牌第一方介面的誘因。

但那個策略，是在客戶工作流程已經改變之後，仍試圖保住舊的價值單位。更可持續的過渡，是對記錄系統、受治理的行動、平台容量、已驗證成果、高價值的人類席位，以及第一方代理的進階功能收費。Salesforce、Microsoft、HubSpot 與 Atlassian 採用點數、行動、對話與成果計費，正反映這個轉變。改變計量方式的供應商，可以歡迎外部代理，而不必把它們視為搶奪席位的賊。

## 建議的技術架構

### 建構業務能力 API，而不只是資料庫 API

API 應公開有意義的操作——對賬一張發票、生成退款報價、批准存取請求、安排維護、驗證配置、關閉支援個案——而不只是建立、讀取、更新、刪除。良好的代理 API 應支援有型別的輸入與輸出、冪等鍵（idempotency key）、試運行或預覽模式、前置條件、明確的副作用聲明、非同步工作狀態、取消、盡可能的回滾、Webhook 與事件、穩定的版本管理，以及機器可讀的錯誤恢復資訊。

業務邏輯應留在 SaaS 產品之內。外部代理應該是*請求*行動，而不是重新實作公司的整個流程。

### 把 MCP 當作轉接層，而非架構本身

MCP 伺服器可以向相容的代理公開產品的工具與資源，但公司應在其下維持一個穩定的內部能力 API。這樣，當標準演變時，產品便得到保護。概念上，各層由外部代理開始，經過 MCP、A2A 與 SDK 轉接層，到達穩定的業務能力 API，再到政策引擎與工作流程運行環境，最後是權威記錄與交易系統。

### 支援多種模型部署模式

成熟的產品可以提供：由供應商託管的 AI（一張賬單、完整支援）；客戶自供的雲端模型（客戶選擇獲批的 OpenAI、Anthropic、Google、Azure、AWS 或其他端點）；在客戶自己環境中運行的客戶私有模型；使用 SaaS 行動 API 的客戶代理，由供應商治理其每一個動作；以及由供應商管理的路由，在多個模型間選擇以優化品質、延遲與成本。並非每種選項都需在每個定價層級提供。

### 把代理視為非人類身分

每個代理都應有自己的身分、擁有者、獲批的用途、適用時的受委派用戶情境、短期憑證、明確的權限範圍、交易限額、到期日，以及完整的行動歷史。系統應區分「用戶執行了此動作」、「代理代表用戶執行了此動作」，以及「自主服務根據常設政策執行了此動作」。

### 把政策圍繞行動建立

與其把代理簡單劃為允許或禁止，不如把政策附加在每個動作上。讀取客戶記錄與起草退款可以自主進行；低於 100 美元的退款可以自主發出；100 至 1,000 美元可能需要經理批准；高於 1,000 美元可能需要財務批准加強化驗證。更改銀行帳戶則絕不可自主進行。

### 把評估內建於生產環境

供應商需要持續量度任務完成率、虛假完成、人手升級、撤銷率、政策違規、客戶更正、延遲、模型與工具成本，以及按模型與按工作流程版本劃分的表現。這套評估系統，很可能成為比提示詞工程更強的護城河。

### 維持成果帳本

對每項可計費的成果，記錄任務請求、預期成功條件、所採取的行動、批准、完成證據、成本、最終狀態、任何其後的撤銷或重開，以及計費事件。這令按成果計費可被稽核，並減少爭議。

### 認證外部代理，而不是禁止它們

存取權可以分級：未認證的代理只有唯讀存取，速率限制很低；已註冊的代理可進行有限的寫入動作並有測試環境；已認證的代理可在獲批範圍內執行生產動作；策略夥伴獲得更高容量與進階工作流程；客戶自行管理的內部代理，則按企業合約管轄存取。這既提供安全，又不把互通性變成非此即彼的決定。

## 建議的商業架構

一個強健的商業設計包含四個部分。

**核心平台訂閱**，對權威數據、工作流程配置、合規、報告、人類席位與平台管理收費。

**代理與 API 執行**，對受治理地使用行動、工作流程、工具呼叫、交易容量與高成本運算收費。無論呼叫者是供應商的代理、客戶的代理、ChatGPT、Claude、Copilot，還是內部自動化服務，都應適用同一收費。

**託管代理服務**，對零配置、模型路由、提示詞與工作流程維護、評估、監控、支援、可預測的成本與更佳的服務水平，收取溢價。

**成果保證服務**，在成功與否可客觀量度之處，按已驗證的結果收費：按每宗已解決個案、每張已對賬發票、每次已完成入門、每條合資格線索、每項已驗證的合規檢查，或按已追回收入或已量度節省的百分比。

託管代理應當因為在經濟與營運上更優越而具吸引力——而不是因為替代方案被人為地停用。

## 多大的毛利才合理？

SaaS 公司可以相對於客戶*完成工作的次佳方式*來定價，而不只是相對於客戶的原始模型成本。假設某項任務由人手完成需 30 美元，客戶自建代理的整體成本為 8 美元。供應商託管的代理可以 5 美元出售該成果，內部成本為 0.75 美元。只要供應商能提供可靠度、整合、實施工夫、支援、治理與風險降低的最佳組合，4.25 美元的毛利便合理。即使相對模型成本的高倍數，也可以是可持續的。

難以持續的，是對 0.10 美元的推理收取 5 美元，卻沒有有意義的驗證、沒有獨特的工作流程、沒有問責，並靠封鎖一切替代方案來維持。

因此，正確的問題不是「相對 token 加價多少百分比才公平？」，而是：*供應商消除了多少商業風險與營運負擔？*

## 各客戶群的市場走向

**小企業**可能會偏好第一方託管代理：一張發票、不用採購模型、不用 API 金鑰、不用基礎設施、簡單的按成果定價。自帶模型可能存在，但採用有限。

**中型企業**會發現混合模式最強。他們想要有支援的預設代理，但也可能使用 Microsoft、ChatGPT、專門的行業代理或內部自動化，而全面禁止會變成競爭劣勢。

**大型企業**會視受控開放為必需。他們關心集中的模型採購、數據駐留、私有網絡、身分、模型批准、成本分攤、稽核與跨系統整合，並可能拒絕堅持採用孤立、不透明代理技術棧的供應商。

**受監管行業**容許供應商更為限制，但勝出的模式很可能是一份經認證的相容性矩陣，而非永久的單一模型鎖定。

**消費者應用**可能繼續由封閉的整合代理服務得很好，因為分銷、便利與產品設計，可能比互通性更重要。

## 未來五至十年的五種情境

**模型快速進步，推理大幅變便宜。** 這是對強制代理收費站最不利的情境。客戶可以廉價地重現簡單的代理行為、通用編排的差異化減少、模型選擇頻繁改變、外部代理更擅長學習新軟件，而 token 加價更易被揭穿。開放的記錄系統、行動 API、工作流程引擎、成果供應商與治理平台勝出；單薄的代理包裝層、只有介面的 SaaS，以及沒有專有執行層的 token 轉售商落敗。

**模型進步，但可靠度依然困難。** 這非常有利於專門的託管代理。模型可能理解任務，卻仍需驗證、例外處理、確定性檢查、人手審查與政策執行，垂直 SaaS 供應商可以捕捉可觀的毛利。互通性仍然重要，因為客戶會使用多個代理。護城河是可靠度，而非排他性。

**一兩個通用企業代理成為主要介面。** 針對特定應用的聊天機器人退居次要，SaaS 產品競逐成為 Microsoft、OpenAI、Anthropic、Google 或內部自建前端背後的首選行動與數據供應者。最佳策略是：讓每個重要的代理都能呼叫你，並對受治理的工作收費。

**監管與數據主權令模型部署碎片化。** 客戶可能按地區、數據分級、部門、用途或監管制度，要求使用不同的模型。與模型無關的架構勝出，而永久與某單一外部模型供應商綁定的產品，則會失去合資格的客戶。

**前沿智能保持集中而昂貴。** 擁有整體採購力量的 SaaS 公司，可能比個別客戶談到更好的模型條件，並可賺錢地銷售託管服務。即便如此，模型抽象層仍然是審慎之舉，否則供應商將依賴其上游供應商。

## 贏家與輸家

可能的贏家包括：**變成行動系統的記錄系統**，因為它們擁有權威資訊與執行權限；**擁有深厚工作流程知識的垂直 SaaS 公司**，它們了解例外情況、法規與成功的定義；**承擔成果風險的供應商**，因為它們可以按客戶價值而非模型成本收費；**多模型治理與路由平台**；**對代理友好的平台**，外部代理成為它們的另一個分銷渠道；以及**評估與可觀察性供應商**，因為當代理採取後果重大的行動，證明它們行為正確變得至關重要。

可能的輸家包括：**純粹的 token 轉售商**，其輸入成本可見、不斷下降，且有許多供應商可選；沒有專有數據、工作流程、交易或評估的**單薄包裝層**；**沒有市場力量的封閉中型 SaaS 產品**；**只有介面的產品**，其互動層可能被通用代理吸收；**無法客觀證明完成的供應商**，因為當賣方單方面定義成功時，客戶會抗拒按成果計費；以及**為保席位而犧牲平台相關性的 SaaS 公司**，它們保住近期收入，卻失去未來的工作流程。

在各種策略選項中，預期價值最高的位置，正是本文一直主張的：受控的開放平台，加上託管與按成果定價的服務。

## SaaS 公司應該怎麼做

**不要一刀切地禁止外部代理。** 改為公布清晰的受支援渠道：REST 或 GraphQL API、SDK、MCP 伺服器、Webhook 與事件，以及經認證的夥伴整合。

**向外部代理收取平台價值的費用。** 外部代理的呼叫不必免費。對受治理的行動、工作流程執行、高成本搜尋、交易量、進階數據檢索，以及稽核與合規功能計量收費。

**令第一方代理成為最容易的選擇。** 它應提供一鍵設定、已知的可靠度、較低的實施成本、自動模型路由、完整支援、清晰的服務水平，以及透明的按成果定價。

**有選擇地容許自帶模型。** 由企業級別和獲批供應商開始，並提供相容性測試、最低模型要求、支援的上下文窗口、工具呼叫要求、安全規則，以及清晰的支援責任劃分。

**保護產品真正的護城河。** 投資於工作流程語意、領域本體、行動權限、例外處理、成果標籤、評估、稽核、整合與交易可靠度。不要過度投資於專有的聊天呈現，彷彿聊天介面就是平台。

**在代理令席位數減少之前，先重建定價。** 邁向由平台訂閱、人類席位、行動容量、託管代理用量與成果組成的混合模式。這可減少與客戶自行控制的自動化對抗的誘因。

## 給管理層的決策測試

在選擇封閉路線之前，管理層應能回答十個問題。如果模型價格再跌 90%，還剩下甚麼獨特價值？競爭對手能否透過開放的代理 API 公開同等功能？產品是擁有權威數據，還是只是展示數據？它是否具備完成交易的法律與技術權限？任務的完成能否被客觀稽核？代理出錯時，公司是否承擔營運或財務風險？客戶是否正統一採用企業級的代理平台？封鎖該代理會令客戶更換代理，還是更換這個 SaaS 產品？外部代理的呼叫能否成為計量的平台收入，而非流失的收入？以及，第一方代理在*沒有*合約束縛的情況下，是否依然更優越？

如果最後一個問題的答案是否定的，那就是最重要、必須解決的產品問題。

## 結語

一個購入基礎模型推理、加上單薄代理層、禁止替代方案，並以差價作加價收入的商業模式，很可能帶來短期變現，卻在長期策略定位上薄弱。它依賴控制門口，而門後的智能正變得更廉價、更可互換。

更好的模式，是維持一個安全、受治理、按商業計量的行動平台，讓任何獲授權的代理都能使用，同時提供一個以最低總成本與最強成果保證取勝的第一方代理。

如果 AI 繼續快速進步，最有可能勝出的公司，不是那些擁有每一個聊天機器人的公司，而是擁有權威情境、工作流程、權限、交易、評估與問責的公司。

最簡潔的原則是：**開放能力層，掌控政策與交易層，並對可信的執行而非被囚禁的智能收費。**
